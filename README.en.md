## 1. In the AI era, those who digitize first benefit first

Everyone is using the same AI. Yet the output differs wildly — and the difference isn't prompt tricks,
it's **how many facts about *you* you've handed it**.

With no records, you get generic advice: "keep a regular sleep schedule", "review your goals".
With records, it can say: "You started 7 plans in the past 6 months and marked 2 as done.
The 5 you didn't finish all stalled around week 3."

The second answer can't be invented by a model. It can only be read out of what you left behind.

**So the earlier you start, the further ahead you get.** Your "personal dataset" is built by time:

- Three months of sleep shows seasonal swings; three weeks only shows you slept badly last night.
- A year of spending shows structural waste; a month only shows money was tight.
- Five years of plan completion shows the kind of work you keep stalling on; one quarter shows nothing.

Data can't be backfilled. One day you'll want to review "how did I actually live these years?"
and realize **the earliest day is already gone** — all you can do is record the first entry today.

This is not another budgeting app, and not a habit tracker. It is **an archive that belongs only to you
and can be fed to AI for years**: daily life, spending, sleep, plans, relationships, ideas — all on one
timeline — and then an honest answer to one question: **where does the life you actually live differ
from the person you think you are?**

## 2. But first, it has to be something you dare to write down

Getting AI to understand you requires writing down the real thing. So this program solves "dare to write" first:

- **Data never leaves your machine.** It listens on `127.0.0.1` only, on a random port each run.
  Egress is off by default — not a single summary is sent anywhere. To use AI interpretation,
  you have to turn it on explicitly in settings.
- **The file is ciphertext.** Each profile is its own encrypted database (whole-database SQLCipher encryption).
  Without the passphrase, reading the file bytes shows no plaintext — not even table names.
  (How it's verified: [ADR-02](docs/adr/ADR-02-sqlcipher.md))
- **The passphrase isn't your only way back.** Creating a profile gives you a one-time recovery key.
  Lose the passphrase but keep the key, and your data survives. Lose both, and it's truly gone —
  by design, not a bug.
- **It doesn't label you.** It won't say "your personality is…". It says "you started 7 plans in 6 months
  and marked 2 as done". The numbers are computed by code; the wording is the AI's job.

## 3. How it works with AI

In one sentence: **you record facts, the program does the math, the model only explains.**

```text
your records  →  code-built fact layer (counts / distributions / trends / week-month-year deltas)  →  AI interpretation  →  plain language for you
```

- **The model never touches raw details.** What goes out is structured facts: counts, active days,
  status distribution, conversions, durations, ratios. Names, notes, diary and dream text,
  `income.total` never leave the machine; sensitive fields are scanned and dropped.
- **Every number is traceable.** Each figure in a conclusion comes from a matching fact-layer entry,
  not from the model's own arithmetic. Hand-written numbers, unverified claims marked "strong",
  or causal phrasing get blocked by the validator.
- **It works without AI.** With no key, no network, or an egress policy set to "never send",
  reports fall back to local rules and say so explicitly ("local mode, degraded") — no fabricated conclusions.
- **Three egress tiers only**: never send (permanently locked for child/teen profiles), aggregate facts only,
  and per-request confirmation.

In other words: **AI gets a statistical summary about you, not your diary.** That's both the privacy
boundary and the reason the conclusions are trustworthy.

## 4. What it does today

- Create a profile (adult / teen / child), unlock, lock, change passphrase, destroy
- Form-based entry: daily life, income, expenses, resources, goal reviews, relationships, health,
  learning, career, interests, plan check-ins, ideas, dreams (the 13 domains of chapter 5).
  Forms are YAML — change the file, change the UI.
  People / hobbies / skills / long-term goals / plans / resources are pickers; create one inline if missing,
  no IDs to memorize.
- Resource and asset ledger: only for large or abstract stocks (car, house, cash pool, available time,
  energy). Day-to-day small amounts go through income/expense. Record a change and the balance accumulates.
- Record "surprises": not exception handling, but part of the record. They are counted separately
  and never silently dropped.
- Browse recent entries, filter by domain, date, keyword, or whether there was a surprise
- Reports: weekly / monthly / yearly. Monthly carries a 6-month trend, empty sections are hidden,
  and the "evidence" block is collapsed into human labels.
- Reports are written by 13 domain analysts, one summary each, then merged by a single integration call:
  domains without data are skipped, and a single failing domain is degraded on its own.
- The report header shows the number of AI calls, input/output tokens and estimated cost, so spend is auditable.
- UI in Simplified Chinese / English / 日本語 / Español; model output follows the UI language.
- Page-level AI interpretation on four pages: reports, self-knowledge, decisions, relationships.
  One button, cached result.
- Encrypted attachments

## 5. Get it running

Requires Python 3.12+ and Node 22+. **Four steps, done:**

```powershell
# 1. Backend dependencies
python -m venv .venv
.venv\Scripts\python.exe -m pip install -e "services/core[dev]"

# 2. Frontend dependencies and build (served by the backend on the same origin)
cd apps/web
npm install
npm run build
cd ../..
```

> Not into typing? Double-click **`LifeOS-setup.cmd`** in the repo root: it checks your Python / Node
> versions, creates the venv, installs dependencies and builds the frontend, and tells you in plain
> language what is missing. Then double-click `LifeOS.vbs`. Add `dev` as an argument to also install
> the test and lint tooling. The script's own messages are ASCII-only English, so they never garble
> on a non-English Windows code page.

Generate some fake data to see what it looks like (**never mix real data in**):

```powershell
.venv\Scripts\python.exe scripts/seed.py --data-dir .tmp/demo --profiles 3 --years 3
```

Run the server (point the data dir at the demo vault, otherwise it opens your real `~/.lifeos`):

```powershell
$env:LIFEOS_DATA_DIR = ".tmp/demo"
.venv\Scripts\python.exe -m lifeos.api
```

It prints one line like:

```
http://127.0.0.1:51234/#t=xxxxxxxxxxxxxxxxxxxx
```

**Open that whole line in your browser.** The `#t=` part is the session token: it is never sent to
the server and never enters browser history (the page wipes it on read). Unlock "Demo profile · Adult"
with the demo passphrase `lifeos-demo`.

> Forgot to copy the line? Open the page directly and paste the token into the box on the home screen.

## 6. One-click start (for people who'd rather not type commands)

The release package is **the whole repo plus a bundled Python**: unzip it and double-click **`LifeOS.vbs`**
in the root folder.

- It starts a local core with the bundled Python that **only listens on `127.0.0.1`**, then **opens your
  default browser** to the UI (the VBS script calls `python.exe` with the window hidden — **no black console**).
- `LifeOS.cmd` is for troubleshooting: `LifeOS.cmd debug` runs in the foreground with visible logs.
  Normal use is just the `.vbs`.
- If double-clicking does nothing, or you want to see where it gets stuck, double-click
  **`LifeOS-debug.cmd`**: it runs in the foreground, keeps the logs in the window, and pauses on errors.
  It has no dependency on VBScript, so it also works when script execution is blocked.
- Python is found in this order: bundled portable build → repo `.venv` → system `PATH`. If none exists,
  it tells you what's missing in plain language instead of showing a blank page.
- First run creates the data directory and an empty profile store. No setup wizard, no "Next".
- To quit, use the **Quit** button in the top-right — it actually terminates the core process.
  **Closing the browser tab does not stop the server** (the UI runs in your system browser).
  It also auto-locks after 10 minutes of inactivity.

> The two commands in "Start today" are the **development path** (running from source, changing code).
> Regular users only double-click the `.vbs`.

## 8. Development

```powershell
# Backend quality gates (all four must be green; use the repo-root venv from services/core)
cd services/core
..\..\.venv\Scripts\python.exe -m ruff check .
..\..\.venv\Scripts\python.exe -m mypy lifeos
..\..\.venv\Scripts\lint-imports.exe
..\..\.venv\Scripts\python.exe -m pytest

# Frontend
cd apps/web
npm run lint && npx tsc --noEmit && npm run test
```

Build the "double-click and go" package (`release/LifeOS/`, whole repo + bundled portable Python;
needs network for the portable Python and dependencies):

```powershell
.venv\Scripts\python.exe scripts/build_release.py
```

Hot reload during development (the backend must already be running; put the real port in):

```powershell
$env:LIFEOS_CORE_URL = "http://127.0.0.1:51234"
npm run dev            # http://127.0.0.1:5173
```

A few rules we set for ourselves, written here so we don't forget:

- The transaction boundary is in `lifeos/domain/`; routes never touch the database directly.
- Only `lifeos/llm/` may use the network; import-linter blocks everything else in CI.
- Logs never contain entry content, amounts, names, or prompts.
- Released migrations, prompts and metrics must not be edited — only new versions (hashes are verified).

## 9. Where data lives, how to delete it, and why there are no accounts

- **Where**: `~/.lifeos/` by default (`C:\Users\<you>\.lifeos` on Windows). Each profile is its own
  **encrypted database** (whole-database SQLCipher); backups live in a **separate directory**
  `data/backups/<id>/`, so a corrupted profile doesn't take its backups down with it.
  To relocate, set `LIFEOS_DATA_DIR` or edit `config.toml.example`.
- **How to delete entirely**: "Destroy profile" in the UI asks for confirmation and the profile alias,
  then **physically deletes** that encrypted database and its backup directory. Deleting the program
  itself does **not** touch `~/.lifeos/` — delete that folder manually if you want everything gone.
- **Why no accounts**: no server, no cloud sync, no login. The program runs only on your machine,
  listens only on `127.0.0.1`, and has egress off by default. So there is **no** "forgot my password,
  contact support" path — you hold the passphrase and the one-time recovery key. Lose them and the data
  is truly unrecoverable (by design, not a bug).

## 10. Child and family mode (a pre-release requirement)

Capabilities for minors — guardian key wrapping, visibility scopes, child report variants — have a
separate [child data compliance checklist](docs/compliance/child-data-checklist.md).
It separates items that are "implemented and covered by tests" from items that
"**must be confirmed by legal before release**". **Until that confirmation is done, do not claim
compliance with any regulation.**

A few hard constraints already in code: egress for child/teen profiles is **permanently locked**
to "never send"; child reports are **not generated unless a guardian asks**; what guardians see is
**an application-level convention, not cryptographic isolation** (a guardian holding the key can
technically read everything).
