# ADR-19：v1 用便携启动器，桌面壳仍待定

- 状态：**已定（阶段性结论）**
- 日期：2026-10-20
- 相关：构建文档 L217（桌面壳待定 ADR-03）、L1616（目录树预留 `desktop/`）、
  P6 计划 3.1/3.2、[ADR-18](file:///d:/AI软件/LifeOS/docs/adr/ADR-18-read-aloud.md)

> **与 ADR-03 的关系**：构建文档的 **ADR-03「桌面壳」仍是「待定」**——本 ADR **不**改它的状态，
> 只记录本期（P6）为「双击即用」所做的**阶段性**选择，避免日后把「没有 `desktop/` 目录」当成漏实现。

## 背景

构建文档默认 v1 只做本地 Web，桌面壳（Tauri 2 + Python sidecar，备选 Electron）留待以后；
目录树里预留了 `desktop/  Tauri 壳（后期）`（L1616）。但 README 自己写着
「还有一件想早点做的事：**双击就能启动**。现在还得敲命令，这对普通人不友好」。

P6 的目标是让**没装过 Python / Node 的普通人双击一个图标就能用**。桌面壳能带来
「关窗即停」与更好的首次体验，但代价高：Rust 工具链、sidecar 交叉打包、代码签名、托盘、单实例
（见 P6 计划 3.1 取舍表）。本期不引入这套重活。

## 决策

**v1 采用「便携启动器」，不动桌面壳选型。**

- 分发形态：**整个仓库** + **随包便携 Python**（`runtime/python/`），双击根目录 `LifeOS.cmd`：
  用随包 Python 起本地核心 → 等握手行 → 自动打开**系统默认浏览器**；用随包 `pythonw.exe`
  拉起以**不出现黑色终端窗口**。
- Python 按「随包便携版 > 仓库 `.venv` > `PATH`」三档查找；起不来时给**可本地化**的失败提示
  （`desktop.error.*`，而非白屏）。
- **不新增任何联网出口**：无更新检查、无遥测、无崩溃上报；`import-linter`「只有 llm 可以联网」
  契约仍然 KEPT。

## 影响

- 因为分发的是**整仓**，仓库根推导（`config.py` 的 `parents[3]`）仍然成立，**不会**出现
  「冻结后路径错位、界面文案全空」的坑；`LIFEOS_*_DIR` 三档回退保留作为显式覆盖。
- 走**系统浏览器**打开界面，因此「关窗即停」做不到：用户关标签页 ≠ 关服务。
  A3 因此定为「**界面内有明确的退出入口**（`POST /api/v1/system/shutdown`）+ 空闲自动锁定」，
  而不是「关窗即停」。要做到后者需自持窗口，即桌面壳——留待 ADR-03 拍板。
- 两个便携 Python 特有的坑需在打包期处理（P6 计划 3.2、事实二）：
  ① embeddable Python 默认不加载 `Lib/site-packages`（`python3xx._pth` 需补进路径）；
  ② 解释器 ABI 必须与依赖轮子一致（`sqlcipher3` 等 native 扩展按 `cp3xx-win_amd64` 编译）。

## 备选方案（不采纳）

- **PyInstaller 打包 exe**：曾起草，因「冻结后路径推断失效 + 未签名 exe 易被安全软件静默拦截
  （Windows 防火墙/电脑管家丢弃 loopback 连接）」而放弃，改为 `.cmd` + 便携 Python。
- **Tauri 2 桌面壳 + sidecar**：留作后续；ADR-03 仍保持「待定」。
