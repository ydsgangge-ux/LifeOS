### 2.3 四个必须先想清的事实

**事实一：启动器与打包物是「契约管不到的地盘」。**
`import-linter` 只分析 Python 包依赖（[pyproject.toml](file:///d:/AI软件/LifeOS/services/core/pyproject.toml#L84-L115)）。
启动器一旦引入更新检查 / 遥测 / 崩溃上报，「数据不出机器」就出现文档里没有的口子，
而且**没有任何现有门禁能自动拦住**。所以必须靠显式检查（见 6.4）。

**事实二（已随 `.cmd` 路线改写）：整仓分发，路径推断反而不用改；真正的坑在便携 Python 本身。**
`.cmd` 路线分发的是**整个仓库**（`services/ apps/web/dist schemas/ config/ i18n/ LifeOS.cmd` + `runtime/python/`），
所以 [config.py](file:///d:/AI软件/LifeOS/services/core/lifeos/config.py#L15) 的 `parents[3]` **仍然成立**，
不存在「冻结后路径错位、界面文案全空」的那种坑；`LIFEOS_*_DIR` 三档回退保留作显式覆盖。
新的两个坑是：

1. **embeddable Python 默认不加载 site-packages**：它带一个 `python3xx._pth` 控制 `sys.path`，
   不把 `Lib/site-packages` 写进去，依赖装进来了照样 `import` 不到，报错却像是「依赖没装」；
2. **解释器 ABI 必须与依赖轮子一致**：`sqlcipher3` 等 native 扩展按 `cp3xx-win_amd64` 编译，
   便携 Python 必须与开发 venv **同版本同架构**，否则原地 `DLL load failed`。

SQLCipher native 库在随包运行时里能否加载，仍是构建文档 15.1（L1824）登记的**中风险**，由 W1.6 冒烟先验。

**事实三：多语言的成本不在「加一个文件」，在四件事。**

| 成本项 | 说明 |
| --- | --- |
| 词表体量 | `zh-CN.yaml` 现有 **960 行**；每新增一种语言就是一次全量翻译 |
| 完整性守卫 | 新增语言后必须保证「键集合 == zh-CN 键集合」，否则会出现裸 key 或静默回退中文 |
| 格式适配 | 日期、数字、货币千分位现在**没有**本地化；表单里的日期控件与图表标签都要跟着 locale 走 |
| 术语一致性 | 儿童报告的措辞禁令（`BANNED_CHILD`）是**中文词表**（[validator.py](file:///d:/AI软件/LifeOS/services/core/lifeos/reporting/validator.py#L23-L26)），换成别的语言后**同一条禁令必须在新语言里依然成立**，否则 P5 的合规结论会在英文界面下失效 |

**事实四：走系统浏览器时，「关窗即停」做不到，只能用「显式退出」。**
如果用系统浏览器打开界面，用户关掉标签页 ≠ 关闭服务；服务会继续持有内存中的会话令牌。
因此本期把 A3 定为「**界面内有明确的退出入口** + 空闲自动锁定（既有 10 分钟机制）」，而不是「关窗即停」。
后者要能可靠实现，需要自己拥有窗口（即桌面壳），见 3.1 的取舍。

### 3.2 路线变更：为什么弃 exe、改 `.cmd`（2026-10-20）

用户原话：「我们这是网页操作的，为什么需要做 exe 程序，做 bat 启动服务器不行吗？」

| # | 理由 | 证据 |
| --- | --- | --- |
| 1 | **未放行的新 exe 会被静默拦掉 loopback 入站** | 冻结产物起服务时 `netstat` 只见 `LISTENING` + `SYN_SENT`，握手行永不打印；`faulthandler` 线程栈停在 `asyncio → _make_self_pipe → socket.socketpair() → _fallback_socketpair → lsock.accept()`；同一份代码用源码/venv 跑完全正常 → 安全软件（Windows 防火墙 / 腾讯电脑管家）丢掉了该 exe 的 127.0.0.1 连接，且**不弹窗** |
| 2 | `.cmd` 最终调的是 `python.exe`，**早已被放行** | 同一台机器、同一份代码，`python -m lifeos.api` 一路通；绕开的成本是零 |
| 3 | 顺带甩掉两个打包坑 | ① PyInstaller 命令行含**中文路径**时会 spawn 失败（`Unable to create process using 'D:\AI??\...'`，返回码 101）；② 冻结形态下自建事件循环的坑不复存在 |
| 附 | 开发体验 | 改代码立即生效，不用每次重跑打包 |

**代价（诚实列出）**：① 分发仍要带一个便携 Python；② 「关窗即停」依旧做不到（事实四不变，仍靠界面内退出 + 空闲锁定）；③ Windows 可能对下载的 zip 弹一次 SmartScreen。

**保留**：`desktop/` 仍按构建文档 L1616 给「Tauri 壳（后期）」预留，不再用于打包；[config.py](file:///d:/AI软件/LifeOS/services/core/lifeos/config.py#L18-L45) 的冻结分支保留给将来的 sidecar 形态。

> **顺手修掉的坑（1.3 的产物自检发现的）**：`lifeos/launcher.py` 原先**没有 `__main__` 守卫**，
> 于是 `python -m lifeos.launcher`（也就是双击入口的那条命令行）只会 import 一遍模块就**静默退出**
> （退出码 0、什么都没发生）；而单测都是直接调 `main()`，看不出这个问题。已补守卫，并加
> [test_module_runs_as_main](file:///d:/AI软件/LifeOS/services/core/tests/test_launcher.py#L313-L330) 用子进程钉住这条命令行。

> **实测发现（W1.6，2026-10-20，结论已修正）**：早先认为「随包 `python.exe` 被安全软件拦掉回环」，
> **这是误判**。逐层探针（`bind+listen` / `bind+connect+accept` / `socket.socketpair()` / `asyncio.run`）
> 在**同一个** `runtime\python` 目录下对照出真正的差异是**解释器文件**，不是目录、也不是网络：
>
> | 解释器 | 回环 `bind+listen` | 回环 `connect+accept` | `socket.socketpair()` | `asyncio.run` |
> | --- | --- | --- | --- | --- |
> | `runtime\python\python.exe` | OK | **OK** | **OK** | **OK** |
> | `runtime\python\pythonw.exe` | OK | **超时** | **永久卡住** | **永久卡住** |
>
> 根因链：本机同时装着 360 与腾讯电脑管家，它们按**可执行文件**粒度过滤回环（防火墙里
> `python.exe` 有 Allow 规则、`pythonw.exe` 没有）→ `pythonw.exe` 的 connect 永远收不到 SYN-ACK →
> CPython 在 Windows 上 `socket.socketpair()` 走的是 `_fallback_socketpair()`（先 `listen` 再
> `connect` 再 `accept`）→ 卡在 `lsock.accept()` 永不返回 → `asyncio` 的 Proactor 事件循环
> `_make_self_pipe()` 建不起来 → uvicorn 连 `run()` 都没进，握手行自然不存在。
> `faulthandler` 抓到的栈完全吻合：`uvicorn/server.py:86 run → asyncio/runners.py:203 run →
> proactor_events.py:784 _make_self_pipe → socket.py:633 _fallback_socketpair → socket.py:298 accept`。
>
> **结论（已落地）**：**弃用 `pythonw.exe`**，改由 [LifeOS.vbs](file:///d:/AI软件/LifeOS/LifeOS.vbs)
> 用 `python.exe` + 隐藏窗口拉起。这样既避开被拦的解释器文件，又满足 A1「不出现黑色终端窗口」，
> 且**不需要用户做任何白名单设置**。把这件事做成 `_loopback()` 探针仍在，但只是环境自检。

## 8. 建议排期顺序

按「先打包、再入口、后语言」推进，每步结束都可跑门禁：

1. **W1**（`.cmd` 双击入口 ✅ + 便携运行时组装 `scripts/build_release.py`）→ **分发包冒烟 + 干净用户双击实测**（事实二的验证前置，别拖到最后）
2. **W2 + W3**（启动器、握手行、退出与错误面）→ 后端门禁 + 桌面实测 S1–S4、S6
3. **W4 + W5** ✅（语言选择入口、词表、格式适配、术语表；`en` 先跑通，`ja`/`es` 已铺开）→ 词表完整性门禁 + 实测 S7
4. **W5b** ✅（提示词语言占位符、locale 贯通出站管线、四语言禁令词表已落地）→ 后端门禁已过；**A6 的真实语言验证（S7b）需在有密钥的环境手动走一次**，沙箱内无法执行
5. **W6**（契约测、端到端、哈希锁定、发布工作流）→ CI 全绿

8. **整体 S1–S8** → 验收 A1–A6（**待真实桌面 / 干净机器 / LLM 密钥**执行）

## 9. 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| **未放行的新 exe 被安全软件静默拦掉 loopback 入站（本机已实际发生）** | 冻结产物起不来，**且没有任何报错**，排查成本极高（只看到 `LISTENING` + `SYN_SENT`） | 3.2：改走 `.cmd` + `python.exe`（早已放行），从架构上绕开；若将来做 sidecar/exe，必须先在目标机放行，并以 `faulthandler.dump_traceback_later` 抓线程栈确认 |
| **`pythonw.exe` 在本机被安全软件按「可执行文件」粒度拦掉回环（已实测确证）** | 用 `pythonw` 拉起时，`asyncio` 的 `socket.socketpair()` 会永久阻塞，核心**连握手行都吐不出来**，表现为双击毫无反应、且没有任何报错 | **已根治**：弃用 `pythonw.exe`，改由 `LifeOS.vbs` 用 `python.exe` + 隐藏窗口拉起（同一目录下 `python.exe` 的回环完全正常，已实跑 `health`/`/`/`shutdown` 全 200）。若将来再做 sidecar/exe，必须用 `faulthandler.dump_traceback_later` 抓线程栈先验，不要假设「换个启动方式就好」 |
| **用户若手动关掉控制台窗口** | 关窗会强杀启动器 → `finally` 来不及跑 → 可能留下孤儿核心占着端口 | W1.2 用 `LifeOS.vbs` + `python.exe` 隐藏窗口拉起（本来就没有控制台可关）；把「退出」收敛到界面内按钮（W3.1/W3.2）+ 空闲锁定 |
| **3 种新语言 × 979 行 ≈ 2900 行翻译量 + 逐键对应** | 工期与质量都容易失控；缺键会静默回退中文，界面出现中英混排 | 先只跑通 `en` 一条完整链路（W5 + W5b），验证后再铺 `ja`/`es`（8 节第 7 步）；键集合门禁（6.3）为唯一硬保障；先做术语表（W5.2）再逐段翻 |
| **`ja` 不能沿用「无 CJK」的断言** | 会写出必然失败、或永远通过的假检查 | `ja` 断言含假名（kana）；只有 `en`/`es` 才断言不含 CJK（见 5.1） |
| 提示词加占位符等于改了已发布模板 | 触碰 ADR-07「已发布版本不得原地修改」，旧报告的模板哈希会对不上 | W5b.1 出**新版本** + W5b.2 登记新哈希，旧版本原样保留；6.5 专门校验 |
| 四语言禁令词表的维护成本 | 漏一种语言，该语言下的合规约束就静默失效 | W5b.6 + W5b.7「构造该语言违规样本必须报错」的断言；清单 8.5 登记 |
| **措辞禁令在多语言下失效（最隐蔽的一条）** | 换成 `en`/`ja`/`es` 后，中文禁令词**匹配不到任何东西**，禁令形同虚设；P5 建立的儿童合规结论与出站报告的校验**双双静默失效**——测试全绿也发现不了 | W5.4 / W5b.6 按 locale 取禁用词表；W5b.7 用**该语言的违规样本**断言必须检出 |
| 模型被要求用某语言输出，但仍回中文 | A6 落空，用户看到的是「界面日文、报告中文」 | W5b.3 注入的是**语言名**而非 locale 码；S7b 用真实供应商各语言各验一次 |
| SQLCipher native 库在随包运行时里加载不了（ABI 不匹配） | 该平台全废（构建文档 L1824 已列中风险） | W1.4 便携 Python 与开发 venv **同版本同架构** + 哈希登记；W1.6 冒烟先验；失败则退回 ADR-02 备选 |
| 便携 Python 的 `python3xx._pth` 不加载 `site-packages` | 依赖「装了却 import 不到」，报错像依赖没装，界面立刻崩 | W1.3 构建时改写 `_pth`；W1.6 冒烟；`test_config_paths.py` 继续守住 `LIFEOS_*_DIR` 覆盖 |
